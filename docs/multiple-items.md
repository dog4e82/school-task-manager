# 한 게시물의 여러 과제·활동

게시물은 원문을 보관하는 단위이고, 과제·활동은 사용자가 준비하거나 신청하는 단위다. 한 게시물의 여러 행동을 하나의 제목·기한으로 합치지 않는다.

## 표시 예

| 한 게시물의 내용 | 목록 표시 |
| --- | --- |
| 보고서 제출 11월 12일 / 코드 제출 11월 19일 | 과제 두 행, 각자의 기한·완료·메모 |
| 로봇 공모전 / 탐구 캠프 | 선택 활동 카드 두 개, 각자의 신청 기한·관심 표시 |
| 서로 다른 대회 두 개가 모두 11월 20일 마감 | 서로 다른 두 활동으로 유지 |
| 한 대회의 교내 의사 전달 / 외부 접수 | 각 기한을 구분한 일정 |
| PDF 형식·이름 표시·분량 제한 | 한 과제의 조건으로 유지 |

과제·활동을 열면 동일한 원문 게시물의 전체 본문을 보여 준다. 각 활동의 기한 영역은 그 활동에 연결된 날짜만 표시한다. 원문 링크를 임의로 새 게시물 주소로 바꾸지 않는다.

## 처리 방식

- 저장된 AI 응답의 여러 항목을 각각 읽는다. 모델은 `gpt-6.1-sol`을 유지하고 기존 프롬프트·분석 캐시 키를 변경하지 않는다.
- 본문·추출된 PDF 페이지의 명시적인 과제 구간을 보정한다. 번호형 구간은 서로 다른 행동과 날짜가 함께 있는 경우 분리한다. 일반 문장만으로 의미가 불명확한 경우 모든 행동을 규칙만으로 구분한다고 보장하지 않는다.
- 활동별로 날짜를 추출·대조한 뒤 목록을 만든다. 다른 활동의 기한을 빌리거나 같은 날짜라는 이유로 활동을 합치지 않는다.
- 기존 단일 활동의 관심 저장 키는 유지한다. 여러 활동으로 새로 분리된 항목은 각각의 ID를 사용하며, 과거 게시물 전체에 저장한 관심 표시를 모든 자식 활동으로 자동 복제하지 않는다.
- 기존 과제 ID는 충돌이 있었던 경우만 구분한다. 동명의 교내 신청·외부 접수가 같은 완료·메모 키를 공유하지 않도록 한다.
- 한 활동이 있다고 같은 게시물의 다른 선택 과제를 숨기지 않는다. 일정으로 대체되는 해당 행동만 중복에서 제외한다.
- 원문을 읽어 표시를 보정하므로 추가 BAZE 생성·과금이나 Classroom 재수집이 필요하지 않다.

## 확인

```powershell
uv run python -m unittest discover -s tests
node --check web/app.js
```

합성 데이터로 단위 검사 169개 및 브라우저 검사 13개를 통과했다. 여러 활동의 같은 날 마감, 본문·PDF 구간 분리, 기한 혼합 방지, 기한 미정인 자식 항목 보존, 독립 관심·완료 저장, 계정별 접근을 확인했다. 실제 학교 데이터로 새 AI 분석은 실행하지 않았다.

## 아직 남은 운영 작업

실제 계정의 Classroom 수집과 기존 분석 재사용을 확인했고, 운영자가 서버 AI 설정 활성화를 알렸다. 현재 정책은 학교 계정의 일일 건수 제한 없이 잔액 2,000크레딧 기준으로 새 생성을 중단하는 방식이다. 긴 PDF는 구간별 분석 후 같은 부모 게시물에 합치며, 각 과제·활동은 독립 항목으로 유지한다. 기본 모델은 `gpt-6.1-sol`을 유지하고 새 모델 학습은 하지 않는다.

Google 브랜딩 게시와 데이터 접근 검증은 별개다. 제한된 PDF 권한과 학교 관리자의 앱 허용도 추가 확인 대상이며, 다른 계정의 실제 수집·분석을 확인하기 전에는 모든 사용자에게 완료됐다고 안내하지 않는다.
